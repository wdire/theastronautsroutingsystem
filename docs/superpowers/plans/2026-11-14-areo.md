# Areo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Areo, a web app to plan, run and walk a science traverse in Jezero crater on real NASA data.

**Architecture:** One Vite single-page app. Pure engines (`src/engines`) do all physics and are unit-tested; a
deterministic simulation (`src/sim`) runs missions; one MapLibre globe (`src/map`) and a lazy-loaded three.js
visor (`src/visor`) draw them; React panels (`src/ui`, shadcn/ui on Tailwind 4) read a Zustand store and never
compute physics. A one-off Python pipeline (`tools/`) writes committed tiles and JSON under `public/`.

**Tech Stack:** Vite 8, React 19, TypeScript 6.0 strict, Tailwind 4, shadcn/ui, Zustand 5, MapLibre GL 6,
three 0.187, Vitest 5, Playwright 1.65; Python 3.14 venv (numpy, Pillow, shapely); two Vercel edge functions.

**Spec:** `docs/build-spec.md` (values) and `docs/superpowers/specs/2026-11-14-areo-design.md` (intent and
departures; wins on conflict). Executors read both. This plan does not repeat the spec's values: each task
names the spec section it implements, and that section is the task's requirement list.

**Execution:** Native, in the main session, with a few subagents for work that is independent, test-defined
and noisy: the data tools (tasks 2 and 3) and the engines (task 4). UI, map, simulation wiring and the visor
are built in the main session, where the look is judged. Subagents never commit; the main session commits
after checking their work. Steps are at deliverable granularity; engines are written test-first.

## Global Constraints

- Mars: radius 3,396,190 m, gravity 3.71 m/s2, sol 88,775.244 s. Times shown as LTST.
- Region 13.1 to 23.8 N, 71.8 to 83.1 E; core 17.3 to 19.6 N, 76.2 to 78.7 E; centre 18.45 N 77.45 E.
- UI in plain English, short sentences, numbers with units, no emoji. Every exaggeration is labelled.
  Anything modelled is labelled "modelled" in the UI and in How it works.
- Every dataset has an entry in `public/data/sources.json` (id, name, mission, product, url, licence, notes,
  retrieved).
- Engines are pure (no DOM, no fetch, no store). UI never computes physics.
- Never disable TLS verification. Retry every download.
- The NASA API key lives only in `.env.local` as `NASA_API_KEY` (gitignored). It never enters the browser
  bundle: only `api/spaceweather.ts` reads it. In dev a Vite plugin serves `api/*` handlers locally.
- Nothing is copied from the pre-event prototype.
- Commits: plain sentences saying what changed for a user and why. No co-author or attribution trailer.
- After each task: `npm run check` (tsc, eslint, vitest) passes, the task's Playwright checks pass, screenshots
  at 1440 x 900 and 390 x 844 are looked at, `docs/progress.md` is updated, then commit.

## Review Focus

Failure modes the spec implies but does not test. Each has a test in the task that owns the code.

1. A route asked from or to a point outside the region, or on ground steeper than the vehicle's blocking
   slope: the planner says so in words and offers the nearest reachable point; the worker never hangs
   (task 6: router unit test and an e2e check).
2. Tiles or data failing mid-session (offline, 404 at a coverage edge, a feed timing out): the map keeps
   drawing from ancestors, panels show a retry line, nothing goes black (task 5: protocol unit tests with a
   failing fetch).
3. Edits racing results: the plan changes while the router is working, or while a mission runs. The newest
   edit wins, stale worker replies are dropped by request id, a running mission is not silently rewritten
   (task 6: store test).
4. Time under stress: 100x across sunset, a backgrounded tab returning after minutes, a departure moved to
   night. The clock never runs backwards and catches up in 60 s sub-steps with a cap per frame (task 7: sim
   unit test).
5. No WebGL, a lost GL context, or a weak phone in the visor: a plain message and a way back to the map;
   context restore rebuilds the scene (task 8: e2e with WebGL disabled).

## Contracts shared across tasks

**Tile package.** `/region/{product}/{z}/{x}/{y}.webp`, XYZ Web Mercator, 256 px. Elevation is terrarium,
lossless WebP. `coverage.json`:
`{ version: string, boxes: { region, core, crater, hirise: [w, s, e, n] }, products: { [product]: { [zoom]: [x0, y0, x1, y1][] } } }`.

**Protocol.** `mars://img/{z}/{x}/{y}`, `mars://dem/{z}/{x}/{y}`,
`mars://derived/{slope|rugged|dose|night|cold}/{z}/{x}/{y}`,
`mars://live/{hirise|themisNight|tesDust|tesTI|molaRough|ctx}/{z}/{x}/{y}`.

**Data files.** `names.json`: `{ id, name, type, lon, lat, diameterKm, minZoom }[]`. `places.json`:
`{ id, name, kind: 'm20' | 'sample' | 'site', lon, lat, elev, sol?, summary, detail?, photos: { src, caption, camera, sol, credit }[] }[]`.
`samples.json`: `{ id, name, sol, lon, lat, rock, campaign, note }[]`. `traverses/m20.json` as in the spec.
`geology.json`: `{ units: { code, name, colour, kind, what, period, age }[], features: GeoJSON FeatureCollection (properties.unit) }`.
`weather.json`: `{ retrieved, rems: Sol[], meda: Sol[] }`, `Sol = { sol, earthDate, minC, maxC, pressurePa, uv?, sunrise?, sunset? }`.
`caves.json`, `sites.json`: `{ id, name, lon, lat, note }[]`.

**Engine types** live in `src/engines/types.ts`, written in task 1 and treated as the contract: `LonLat`,
`PathPoint` ([lon, lat, elev]), `VehicleId` ('foot' | 'openRover' | 'pressRover' | 'robotRover' | 'heli'),
`RouteStyle` ('safest' | 'fastest' | 'eco'), `Scenario`, `TaskKind`, `Task`, `Stop`, `MissionPlan`,
`TripSample`, `TripResult`, `Grid`, `RouteAlternative`, `Severity` ('note' | 'advisory' | 'caution' |
'warning'), `Alert`, `World`, `Crew`. A task that needs a new shared type adds it there.

**Store.** One Zustand store, slices `view`, `clock`, `scenario`, `planner`, `mission`, `layers`, `ui`;
exposed as `window.__areo`. Worker replies carry the request id they answer.

**Visor.** `mountVisor(canvas, deps): { setCamera, setQuality, resize, dispose }`, loaded with `import()`.
Tests reach it as `window.__areoVisor`.
